**Статус:** ЧАСТИЧНО ИСПРАВЛЕНО; статические проверки CI пройдены, реальный браузерный offline QA ожидается.

Обновлён `sw.js` до `dead-calm-visual-v95`. Precache теперь содержит 126 same-origin путей: корневую страницу, manifest и все файлы под `src/` (JS, CSS, JSON и графические ассеты). Добавлен `tests/service-worker-assets.test.mjs`: проверяет JSON-список, уникальность путей, наличие файлов в репозитории, наличие ключевых entrypoint-файлов, версию кеша и fallback. GitHub Actions run `44623940007` завершился с `success` на коммите `43681d3`; в дереве 48 тестовых файлов.

Этот внешний CDN не включён в same-origin precache, поэтому полная офлайн-визуальная идентичность пока не гарантирована. Это отдельный release QA/production decision; не объявлять PWA полностью offline-ready до браузерной проверки и решения по Tailwind CDN.

**Критерий закрытия:** статическая целостность precache выполнена. Полное закрытие требует браузерной проверки install/activate/update/offline и проверки Tailwind/внешних зависимостей.

## 3. Архитектура и содержание: наблюдения

### Сцены и маршрутизация
- Маршрутизатор импортирует сцену динамически из `src/js/scenes/<name>.js`.
- В дереве 15 сцен, включая основные игровые сцены и прототипы.
- Есть отдельные сцены `minigame-test.js` и `investigation.js`; их релизная необходимость не подтверждена.
- `crime-scene.js` — крупная сцена (около 1 300 строк на момент чтения). Не переписывать автоматически; сначала проверить реальный пользовательский путь и зависимости.

### Главное меню и кабинет
- Главное меню содержит «Новая игра», «Продолжить», «Настройки».
- Кабинет содержит карту, доску, архив улик, дневник, хронологию, дела и три карточки мини-игр.
- В кабинете встречаются статические значения/тексты, например «Доступно локаций: 5» и «Событий: 10». Нужно сверить с реальным состоянием и убрать фиктивные показатели или привязать их к данным.
- Карточки мини-игр должны быть проверены на сюжетную необходимость: не всякая активность обязана оставаться в релизе только потому, что уже имеет кнопку.

### Сохранения
- `Storage` оборачивает localStorage и ловит ошибки сериализации/чтения.
- Ошибка чтения сейчас возвращает `null`; нужно убедиться, что UI отличает повреждённое сохранение от отсутствия сохранения и предлагает безопасное восстановление.
- `GameState.reset()` очищает все ключи с префиксом `deadCalm_`, затем записывает пустое состояние.
- Необходимо проверить версионирование схемы и миграции реальных старых сохранений. Одних нормализаторов отдельных подсистем недостаточно, чтобы считать миграцию всего save формата завершённой.

### Мини-игры
- В дереве присутствуют три утверждённые активности: mechanical repair, radio tuning, film restoration.
- Общий модуль `minigame-progress.js` ограничивает допустимые типы этими тремя активностями.
- По документации и комментариям проекта некоторые визуальные решения всё ещё CSS mockup; наличие рабочей логики не означает готовность финального арта, аудио или интеграции в сюжет.
- До 1.0 не создавать четвёртую активность.

### Граница с Ghost Signal
- В проекте есть карта, доска расследования, архив улик, дневник, сцены поиска и множество подсистем расследования.
- Само наличие кода не означает, что всё это следует удалить: часть может быть нужна для текущего сюжета.
- На Этапе 0 нужно проверить реальный путь игрока и решить для каждого элемента Keep / Finish / Simplify / Remove / Deferred. Не расширять эту структуру новыми похожими системами.

## 7. Повторная проверка сохранений — 2026-11-20

После подключения автотестов обнаружен ещё один риск DC-AUDIT-001: `Storage.load()` возвращал `null` и для отсутствующего сохранения, и для повреждённого JSON. Главное меню в таком случае могло показывать обычное «Нет сохранений» либо разрешать Continue на пустом состоянии. Ошибка доступа к localStorage также не отличалась от отсутствия данных.

Исправлено в рабочей ветке:
- `Storage.inspect()` различает `missing`, `valid`, `corrupt` и `unavailable`; старый `Storage.load()` сохранён как совместимый интерфейс;
- запись, проверка, удаление и очистка хранилища обрабатывают ошибки браузера и не выбрасывают их в игровой поток;
- `GameState.init()` не перезаписывает повреждённые данные автоматически, выставляет статус и создаёт безопасное временное состояние в памяти;
- Continue доступна только при валидном объекте сохранения; повреждённое/недоступное хранилище получает отдельное предупреждение;
- начало новой игры при существующих данных требует подтверждения, включая повреждённое сохранение;
- добавлены регрессионные тесты на повреждённый JSON, некорректные типы, заблокированное хранилище, запрет молчаливой перезаписи и доступность Continue только для валидного сохранения.

**GitHub Actions run `44722626140` — SUCCESS, 284/284 тестов, 0 failures.** Дополнительный тест `GameState.hasSave` добавлен после этого прогона; его итоговый запуск ожидается.

**Ограничение:** автоматические тесты не заменяют проверку в реальном браузере с повреждённым localStorage, приватным режимом и ограничением квоты. DC-AUDIT-001 остаётся без полного runtime sign-off до ручной проверки.

**Итоговый CI после добавления проверки `GameState.hasSave`:** run `44722722219` — SUCCESS, 285/285 тестов, 0 failures. Повторный прогон документационного коммита `e7fc476`, run `44722755688`, также SUCCESS, 285/285.

## 10. Исправление порога доказательства радиоприёмной — 2026-11-20

Повторная проверка связки «мини-игра → улика» выявила несоответствие: радиосистема считала сигнал неразборчивым ниже 68 баллов, но слой наград выдавал улику уже с 38 баллов. Это позволяло получить доказательство без достаточной слышимости передачи.

Исправлено:

- чистый приём требует исхода `clear` и качества не ниже 92;
- сохранена возможность фрагментарного исхода с высоким числом качества, если фильтр не вошёл в диапазон фиксации;
- добавлены проверки границ 67/68/91/92 и несовпадающих исходов.

Также ужесточена согласованность исходов киноплёнки: улика принимается только для фактических исходов `success` или `partial` с соответствующим порогом качества. Это не позволяет передать противоречивую пару «исход/качество» и получить более сильное доказательство.
